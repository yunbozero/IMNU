# 猫猫图鉴的照片

## 两种放照片的方式

图鉴的照片有两个来源，**优先级只有一条：有覆盖用覆盖，没有就用这里。**

| | 放哪儿 | 换一张要做什么 | 适合 |
|---|---|---|---|
| **默认照片** | 本目录，文件名写进 `cats.js` | 改代码 → 重新发布 | 上线时就有图的那一批 |
| **覆盖照片** | 管理员在**小程序里**传（存数据库） | 点几下，立刻生效 | 平时随手换 |

覆盖照片走「我的 → 管理端 · 图鉴照片」（副主任及以上）。
它每次上传都生成一个带随机串的新文件名，所以不受下面那个缓存问题影响。

### 默认照片怎么加

把照片放进这个目录，文件名写进 `miniprogram/data/cats.js` 的 `image` 字段
（写 `cats/文件名`），发布时 `deploy/deploy.sh` 会把它们同步到服务器的图片目录，
由 nginx 直接发。

```js
// miniprogram/data/cats.js
{
  id: 'c1',
  name: '大橘',
  image: 'cats/daju.jpg',   // ← 就是这里
  ...
}
```

> ⚠️ 这里换图是**同名替换**，而 nginx 对图鉴目录设了 1 小时缓存
> （物品照片是 30 天，因为它们的文件名每次都不同）。
> 所以换完图最多一小时才全量生效 —— 想立刻生效就用小程序里的覆盖。

### 加照片的步骤（就这四步）

1. 照片压到 300KB 以内（宽边 600–800px 就够），拷进本目录。
   文件名**自己起成全小写英文**，比如 `daju.jpg` —— 别用手机原图名，
   也别用中文名（原因见下一节）。
2. 在 `miniprogram/data/cats.js` 里给这只猫写上 `image: 'cats/daju.jpg'`。
   已经存在的猫改这一行；新猫照抄一条改字段。
3. 跑一次 `node tests/all.mjs`。
   ★ 不用等发布：这一步会检查**你写的名字和目录里的文件名是不是逐字一样**，
   大小写不同也会被抓出来（比如写成 `Daju.jpg`）。查不出来的时候它会把
   目录里真实的名字打给你看。
4. 提交、发布。

第 3 步挡住的正是最难查的那类错：名字差一个字母、或者大小写不同，
**开发机是 Windows（大小写不敏感）一路绿灯，上了 Linux 服务器才 404**，
而界面上只会回落 emoji，一句报错都没有。

## 文件名必须是纯 ASCII

**只能用小写字母、数字、下划线、短横线**，扩展名 `.jpg` / `.png` / `.webp` / `.gif`。
例如 `daju.jpg`、`cat_01.jpg`、`xiao-hei.jpg`。

### 为什么（这个坑很隐蔽）

小程序的 `<image>` 会把中文文件名做**百分号编码**，而服务端的静态图片服务
**故意不做 URL 解码** —— 那是为了从一开始就不存在路径穿越问题
（见 `server/images.mjs` 和 `server/http.mjs` 的 `sendImage`）。

两边一撞的结果：`cats/大橘.jpg` 会请求成 `/images/cats/%E5%A4%A7%E6%A9%98.jpg`，
直接 **404**，而界面因为「加载失败回落 emoji」**不会报任何错** ——
你只会看到那只猫一直没有照片，完全想不到是文件名的问题。

`tests/miniprogram.test.mjs` 有两条守卫盯着这个：一条查名字的**格式**
（不许中文大写），一条查名字**和实际文件对不对得上**（含大小写）。

**小写也是必须的**，不只是"建议"：Linux 上 `Daju.jpg` 和 `daju.jpg` 是两个
不同的文件，而 Windows 上不是 —— 所以大小写写错在开发机上永远发现不了。

## 大小建议

**压到 300KB 以内，宽边 600–800px 就够。** 图鉴列表一屏好几张，
原图（三五 MB）在校园网上会明显卡顿。`deploy.sh` 遇到超过 300KB 的会提醒，
但不拦。

手机上压缩最省事的办法：微信发给自己一遍（会压），再存回相册。

## 目录里没有照片时

`image: null` 就回落成 `emoji` + 底色那个色块 —— 断网、加载失败也一样回落，
所以**图鉴永远能看**，不会出现一片空白。

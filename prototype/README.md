# IMNU 校园义卖 · 前端原型

可点击的 HTML 原型，用于向义卖组织方演示流程。**纯前端，不接任何后端**，所有状态存在浏览器 localStorage 里。

设计语言参考 IMNU 猫咪图鉴：陶土橙主色 + 暖米底 + 白色大圆角卡片 + 微信胶囊导航。

---

## 怎么打开

推荐用内置的零依赖静态服务器（`localStorage` 需要 HTTP 环境）：

```powershell
npm run serve
# → http://localhost:8080/
```

首页是**演示台**：左侧是页面导航，右侧是手机边框预览。给组织人演示时用一个电脑屏幕就能讲完全流程。

> 直接双击 `index.html` 也能看，但部分浏览器在 `file://` 下禁用 localStorage，会导致预定状态在不同页面之间丢失。所以优先用 `npm run serve`。
>
> 也可以把 `prototype/pages/*.html` 单独发到手机上打开，逐页感受真实手感。

---

## 建议的演示顺序

跟着这条线走，正好是一个完整闭环：

1. **S2 逛义卖** —— 搜索、按摊位筛选、剩余名额进度条
2. **S3 物品详情** —— 点"预定名额"
3. **S4 确认预定**（弹层）—— 选数量，确认提交
4. **S5 预定成功** —— 重点讲：这里明确写着"你还没有付款"
5. **S7 取货码** —— 二维码 + 6 位数字码，屏幕自动调亮
6. **S6 我的预定** —— 待取货 / 已取货 / 已取消 三个分组
7. **V1 核销台** —— 点"扫码核销"（模拟扫到一位同学的码）
8. **V3 核销结果** —— 满屏绿色对勾，3 秒自动返回
9. 回到 V1，点"手动输入取货码"，按页面上的演示提示输入那两串数字，演示**核销成功**与**已核销过**两种分支

想重新来一遍，点演示台左下角的**「重置演示数据」**。

## 怎么把原型展示给别人看

| 方式 | 可行 | 说明 |
| --- | --- | --- |
| 把 `.html` 文件直接发微信 | ❌ | 微信不渲染 HTML 附件，对方点开只会看到「不支持预览」。而且拆成多个文件+相对路径，换设备就散了 |
| 发一个在线链接 | ⚠️ | 需要域名能在微信内置浏览器正常打开。未备案域名不友好；CloudBase 默认域名会弹「访问提示中间页」，官方也说明默认域名只建议用于开发测试 |
| **面对面扫码** | ✅ | 最快，零成本，见下 |
| **录屏 / 截图** | ✅ | 远程沟通最稳，100% 能看 |
| 小程序体验版 | ✅ | 最终形态，微信里原生打开，但要先做完真小程序 |

### 面对面演示（推荐首选）

```powershell
npm run serve
```

启动后终端会打印出局域网地址，形如 `http://192.168.1.23:8080/`。
让对方手机连上**同一个 WiFi**，用微信扫一扫、相机扫码，或直接把地址输进手机浏览器即可。
不经过微信服务器、不需要域名、不需要备案。

### 远程发送

用系统自带录屏（`Win + G`）或 OBS，按上面的"建议的演示顺序"录 60–90 秒，连同几张关键页面截图一起发微信。
对方能反复看，也方便转发给社团其他人。

## 原型里"假"的部分

- 所有物品、摊位、其他同学的预定记录都是 `assets/data.js` 里的假数据。
- 物品图片用**色块 + emoji** 占位，不依赖任何网络图片，离线也能演示。
- 二维码是由取货码字符串确定性生成的**伪二维码**，扫不出真实内容。
- 提交预定有 550ms 的假延迟，用来演示按钮防连点。
- "屏幕亮度自动调高"只弹了个提示，真实小程序会调 `setScreenBrightness`。
- 核销记录里的操作人固定写成"志愿者 陈亦航"。

## 已经做进去的真实规则

这些不是装饰，是后面接后端时要落到服务端的逻辑，现在已经可测：

- 名额扣减（约满时拒绝，不会扣成负数）
- 同一件物品不能重复预定
- 取消预定会把名额还回去，且重复取消无效
- 核销是单向状态转换，同一个码只能用一次
- 无效码、已取消的码都核销不了

## 合规约束（重要）

个人主体小程序不能涉及金额交易，所以原型里**刻意不存在**任何价格、金额、支付相关字段和文案。界面用词统一为：**预定 / 名额 / 取货码 / 核销 / 摊位**。

这条约束有自动化测试守着，见 `../tests/prototype.test.mjs` 的"合规红线"部分——改动时如果不小心写了禁用词，`npm test` 会直接失败。

# 校园义卖预定小程序 · 前端原型方案

> 状态：方案待评审（未开始编码）
> 适用阶段：MVP，用于向义卖组织方演示与争取合作
> 主体：内蒙古师范大学 · 个人主体小程序

---

## 1. 前提与约束

| 约束 | 来源 | 对界面的直接影响 |
| --- | --- | --- |
| 个人主体小程序 | 已确认 | 不能涉及金额交易，界面上**不出现任何价格数字** |
| 系统不碰钱 | 已确认 | 无支付、无订单、无对账；付款全部在线下摊位完成 |
| 并发量不大 | 已确认 | 不需要排队/限流类界面 |
| 本版范围 | 已确认 | 学生端 + 志愿者核销端；管理后台暂不做界面 |

**一句话定位**（界面内外都要反复强化）：
本小程序只做「**锁定名额**」，不做交易。预定免费，取货当天到摊位现场付款。

## 2. 页面地图

```

  S1 身份登记 ──► S2 首页

                                                                      │
                                                                      ▼
```

## 3. 学生端页面详述

### S1 身份登记（仅首次进入）
- **目的**：拿到可线下核对的真实身份，同时把「不涉及交易」讲清楚。
- **内容**：欢迎语 + 活动名称；学号输入；姓名输入；学院/班级（选填）；《活动规则》勾选。
- **主按钮**：开始逛义卖
- **必须出现的一句话**：
  > 本小程序仅登记预定名额，不出售商品、不收取任何费用。
- **状态**：学号重复 → 提示「该学号已登记，请联系管理员」。

### S2 首页 / 义卖物品列表
- **顶部活动信息条**：活动名称、时间、地点、主办方（可折叠）。
- **搜索框**：按物品名搜索（物品量不大，够用）。
- **筛选**：按摊位切换（全部 / 一号摊位 / 二号摊位 …）；可选按分类（手作 / 二手 / 文创 / 食品 / 其他）。
- **物品卡片**（每张）：
  - 主图、物品名、所属摊位
  - **剩余名额**：文字「还剩 5 / 20」+ 细进度条（**不用"库存"这个词**）
  - 状态标记：`可预定` / `已约满`（置灰、不可点）/ `已结束`
- **下拉刷新** + 上拉加载。
- **空状态**：活动未开始 / 已结束 / 无匹配结果，各写一句不同的引导语。

### S3 物品详情
- **图片轮播**（1–5 张）。
- **核心信息区**：物品名、所属摊位 + 摊位位置、**剩余名额**、取货时间（活动当天的时间段，若未分时段则写活动时段）。
- **描述区**：成色/规格/备注（如"9 成新，含笔记"）。
- **重要提示条**（固定出现，视觉上要有分量）：
  > 预定免费，仅锁定名额。请于义卖当天凭取货码到摊位现场付款取货。
- **底部固定操作栏**：
  - 可预定 → 「预定名额」主按钮
  - 已约满 → 按钮置灰「已约满」
  - 我已预定过 → 按钮变为「查看我的取货码」（跳 S7）
- **交互**：点击「预定名额」弹出 S4。

### S4 确认预定（半屏弹层，不单独成页）
- 物品摘要（缩略图 + 名称 + 摊位）
- 数量选择：1 件 / 2 件 …（上限由物品名额和管理员配置决定；若全局规则是"每样限 1 件"则不显示此项）
- 取货人信息确认：姓名 + 学号（来自 S1，可跳去修改）
- 一行规则复述：预定成功后请按时取货，无故未取货会影响后续活动参与。
- 按钮：`确认预定` / `取消`
- **交互**：提交中按钮进入 loading 且禁用（防连点）；结果分三种，**文案必须区分**：
  - 成功 → 跳 S5
  - 已被抢完 → 弹层内红色提示「手慢了，名额刚刚被约满」，并刷新剩余名额
  - 已预定过 → 「你已经预定过这件物品」，提供直达 S7 的入口

### S5 预定成功（独立页，仪式感 + 消除"已付款"误解）
- 顶部大对勾 + 「预定成功，名额已锁定」
- **醒目提示**：「尚未付款。请于义卖当天到摊位现场付款取货。」（这一点必须无法被忽略）
- 摘要卡片：物品名、摊位、取货时段、取货码（数字码，大字）
- 按钮：`查看取货码`（跳 S7） / `继续逛`
- **备注**：此页可否与 S7 合并为一个页面，见第 8 节待确认项。

### S6 我的预定
- **分段切换**：`待取货` / `已取货` / `已取消`（默认落在待取货）。
- **每条记录**：物品缩略图、名称、摊位、取货码（小字）、状态标签。
- **点击** → 进入 S7。
- **待取货条目上直接给一个「出示取货码」按钮**（活动当天这是最高频路径，不要让人多点一次）。
- **已取消条目**：显示取消原因与时间，不可再操作。
- **空状态**：还没预定 → 按钮「去看看有什么」。

### S7 取货码详情（全屏凭证页，视觉优先级最高）
- **这是整个小程序最关键的一屏。**设计要求：志愿者在户外强光下、3 秒内能读出来。
- **结构**：
  - 状态区：`待取货` / `已核销（时间）` / `已取消`
  - **二维码**：供志愿者扫码核销（在线通道）
  - **数字码**：6 位，超大字号、字间距拉开、分组显示 `482 913`（离线通道，学生口报）
  - 说明文字：「网络不好时，可直接向志愿者报这串数字」
  - 物品名 + 摊位 + 摊位位置 + 取货时段
  - 取货人：姓名 + 学号后四位（**供志愿者核对，防止有人拿别人的码**）
- **交互增强**：
  - 进入此页自动把屏幕亮度调到最高（小程序 `setScreenBrightness`），退出时恢复
  - 二维码建议做**动态刷新**（防截图转发），若成本高可放在 MVP 之后
  - 底部次按钮「取消预定」（二次确认，明确告知名额会释放给别人）

### S8 我的
- 头像/昵称（微信授权）、姓名、学号（可修改，修改后需重新核对）
- 我的预定入口
- **志愿者入口**：仅当账号有核销角色时显示，点击进 V1
- 活动规则说明页入口
- 关于我们 / 主办方信息

## 4. 志愿者端页面详述

> 志愿者端的设计目标只有一个：**忙的时候不出错、不卡壳。** 严格服从「大字号、强对比、单一大按钮、结果无歧义」。

### V1 核销台首页
- 顶部：我的摊位（如「一号摊位 · 图书馆前广场」）+ 今日已核销数量
- **超大主按钮**：「扫码核销」
- 次按钮：「手动输入取货码」（网络差 / 学生码打不开时的降级通道）
- 底部入口：「核销记录」

### V2 扫码 / 输码
- 扫码：调起 `scanCode`，识别取货码。
- 输码：6 位数字键盘输入，分组显示，自动跳格。
- 提交后进入 V3。

### V3 核销结果（全屏结果页，一眼可辨）
- **成功**：
  - 满屏绿色 + 超大对勾
  - 「核销成功」
  - 物品名 + 数量
  - 取货人姓名 + 学号后四位（**志愿者据此核对实物与身份**）
  - 提示：「请确认已收款后再交付物品」
  - 3 秒后自动返回，或点「继续核销」
- **失败**，必须区分原因并给出下一步：
  | 原因 | 文案 | 下一步动作 |
  | --- | --- | --- |
  | 已核销过 | 此码已于 14:32 核销 | 显示核销时间与操作人；提供「撤销核销」入口（权限受限） |
  | 已取消 | 该预定已被学生取消 | 无 |
  | 无效码 | 取货码不存在，请核对数字 | 返回重输 |
  | 非本摊位 | 该物品属于三号摊位 | 提示去对应摊位（若启用按摊位分权） |

### V4 核销记录
- 今日核销流水：时间、物品、取货人、操作志愿者
- 最近一条可「撤销核销」（需二次确认；更早的需管理员）
- **撤销必须留痕**，界面提示「撤销操作会被记录」。

## 5. 跨页面的关键交互设计

| 场景 | 设计 |
| --- | --- |
| **无网 / 弱网** | 取货码页离线可看（数字码本地渲染）；核销端弱网时要有明确 loading 与超时提示，**禁止无反馈地失败** |
| **防连点** | 所有写操作按钮：提交中禁用 + 明确的结果反馈 |
| **售罄** | 列表卡片置灰 + 详情页按钮置灰，不隐藏（让学生知道有这件东西，只是没有了） |
| **一人一件** | 已预定过的物品，详情页按钮变成「查看我的取货码」 |
| **名额释放** | 取消预定后，列表剩余名额要能刷新体现 |
| **状态可视化** | 学生只需理解 3 个状态：待取货 / 已取货 / 已取消。不要暴露内部状态机 |
| **亮度** | 取货码页自动调亮，离开恢复 |

## 6. 文案与合规红线

**禁用词 → 替代词**（全站，包括按钮、提示、空状态）

| 禁用 | 替代 |
| --- | --- |
| 订单、下单、购买、结算 | 预定、登记 |
| 支付、付款（指线上）、付款成功 | 仅在线下语境使用「现场付款」 |
| 价格、金额、¥、元 | **完全不出现** |
| 库存、剩余库存、发货、收货 | 名额、剩余名额、取货 |

**固定出现的合规声明**（至少出现在 S1、S3、S5）：
> 本小程序仅登记预定名额，不出售商品、不收取任何费用。请于义卖当天凭取货码到摊位现场付款取货。

**绝对禁止**：任何收款码图片、任何线上付款引导、任何金额输入框。

## 7. 视觉方向（待你提供 UI 参考图后定稿）

暂定基调，供你拿参考图时对照：

- **整体**：校园公益感 —— 温暖、干净、圆角、大图、留白充足；避免冷硬的电商风。
- **主色**：待定（等你确认学校品牌色或参考图配色）。
- **视觉优先级排序**：`取货码页` > `核销结果页` > `物品列表卡片` > 其余。前两屏值得单独精雕，其余保持克制一致。
- **字号**：志愿者端整体比学生端大一号（户外使用、时间紧）。
- **图标**：优先用文字 + 少量线性图标，减少自定义插画工作量。

## 8. 原型交付形态（HTML 可点击原型）

```
prototype/
  index.html          演示外壳：左侧页面导航 + 右侧手机边框预览（给组织人用电脑看）
  assets/
    style.css         设计变量（主色/圆角/字号/间距）+ 组件样式
    app.js            页面切换、弹层、伪造的交互反馈
  pages/
    s1-signup.html    ... 各页面独立文件，也可单独在手机上打开
```

**为什么这样组织**
- 给组织人演示时打开 `index.html`，一个电脑屏幕看完全流程，最省事。
- 每个页面文件可独立打开，方便在真机上感受和逐页截图。
- 假数据用真实的义卖物品（手作曲奇、二手教材、多肉盆栽、文创帆布包、限量柠檬茶…）和真实摊位名，避免 Lorem Ipsum 式的假。
- 交互反馈（预定成功、售罄、核销成功/失败）在原型里用前端 JS 伪造，**不接后端**。

# 盛师猫猫 · 校园义卖预定小程序

内蒙古师范大学的校园义卖活动：学生在线**预定名额**、拿到取货码，活动当天凭码到摊位
**线下付款取货**。小程序不涉及在线支付，只负责锁名额与核销。

已经部署在阿里云上运行。小程序名称「盛师猫猫」，类目是「工具 > 预约/报名」与
「工具 > 信息查询」，线上域名见 `miniprogram/config.js`。

> **主体是个人主体小程序**，所以界面里不能出现任何价格、金额与线上交易。
> 这不是取舍，是审核硬约束 —— 而且**有测试守着**：界面文案里出现交易用语就红。
> 产品的形态其实是被这条约束反过来塑造出来的，见下一节。

## 这个项目的做法有什么不一样

**1. 「不能收钱」倒逼出了整个产品形态。**
个人主体拿不到微信支付、拿不到手机号能力、界面上不能出现金额。所以「在线付款」
这条路根本不存在，设计只能反过来：线上只锁一个名额，钱和货都在活动那天线下完成。
**取货码成了线上与线下的接缝** —— 这也是为什么身份识别只能用「昵称 + 取货码」，
而不是手机号或学号。

**2. 全仓库零第三方依赖。**
后端用 Node 内置的 `node:sqlite`，没有 `npm install` 这一步；唯一的第三方代码是
一个 vendored 的单文件二维码库（画取货码用）。数据库也只有一个 SQLite 文件。

**3. 测试不是覆盖率，是不变量。**
见下面「测试证明了什么」—— 那几条是在验证核心命题，不是「跑一下不报错」。

## 它做什么

| 角色 | 能做什么 |
| --- | --- |
| 学生 | 浏览物品 → 预定名额 → 拿取货码；活动当天凭码取货；同一件物品一人一次 |
| 志愿者 | 扫码 / 手输取货码**核销**；维护「猫猫图鉴」 |
| 二级管理员 | 看预定名单、取消误定的预定、加减物品名额、上下架、新建物品 |
| 一级管理员 | 建活动与摊位、撤销误核销、改每账号预定上限、**给账号开权限** |
| 超级管理员 | 全局唯一；换届时把身份**转交**给下一届 |

权限分五档，判定收在 `server/roles.mjs` 一个纯模块里，所有角色组合由测试穷举 ——
权限写错的后果不是「界面难看」，而是「有人能删掉不该删的人」。

顺带做了个**校园猫图鉴**（和义卖共用一个后端）：管理员在小程序里加猫、改资料、
传照片，改完立刻生效、不用发版。图鉴的内容由管理员自己维护。

## 跑起来

```bash
npm test          # 全部测试（607 项）
npm run serve     # 打开 http://localhost:8080/ 看原型演示台
npm start         # 起后端接口
npm run dev       # 本地开发用这个：node --watch，改完 server/ 自动重启
npm run longimage # 重新生成微信长图（PNG 属于构建产物，不入库）
```

需要 **Node 22+**（后端用了内置的 `node:sqlite`）。**没有 `npm install` 这一步。**

本地起后端：

```powershell
$env:SESSION_SECRET = "随便一个 16 位以上的字符串"
$env:DB_PATH = ".\tmp\bazaar.db"
$env:PORT = "3000"
npm start
```

不配 `WX_APPID` / `WX_SECRET` 也能起，只是 `/api/login` 会失败，其余接口照常 ——
本地联调时用 `DEV_FAKE_LOGIN=1` 走假登录（它拒绝在 `NODE_ENV=production` 下启动）。

## 测试证明了什么

`npm test` 里有几项是在真的验证核心命题：

- **8 线程 × 15 次并发抢 20 份名额 → 恰好卖出 20 份**，失败原因全是「约满」
  （真多线程，不是假装并发）
- **8 线程抢着核销同一个取货码 → 只有 1 次成功**
- **绕过应用层直接写 SQL 扣名额 → 数据库拒绝，名额不会变负**（第二道防线）
- **随机 400 步操作，每一步之后账目都必须平衡**（预定扣、取消还、核销不动）

## 几个设计选择，和为什么

- **防超卖做了两道，而且互相独立。** 应用层是一条带条件的原子 UPDATE
  （`WHERE remaining_quota >= qty` 并检查影响行数）；数据库层是
  `CHECK (remaining_quota >= 0)`。第一道写错时第二道还会拦 —— 有一条测试专门
  「绕过应用层」来证明第二道不是摆设。

- **时间一律按北京时间。** 服务端解析时间时硬编码 `+08:00`，客户端只发
  `"YYYY-MM-DD HH:MM"` 字符串、从不发时间戳。服务器时区改成 UTC 也不会算错。

- **图片在客户端压缩，服务端只认魔术字节。** 手机原图三五 MB，活动现场的网络传不动。
  服务端不看扩展名、也不看客户端声称的 content-type，只看文件头；文件名由服务端
  自己生成。于是**路径穿越在结构上就不可能发生**，不需要靠过滤来防。

- **猫猫图鉴存服务端，不编译进小程序包。** 图鉴是 tabBar 一级页面、内容会一直变，
  而发一次版要等 1–2 天审核。代价是图鉴页要多发一次请求 —— 所以客户端先用本地缓存
  渲染、再异步刷新，断网也还能看。

- **自建后端而不是云开发。** 数据在自己手里；零依赖也意味着几年后还能跑起来。

## 小程序平台上踩过的坑

这几条都是「不写测试就一定会踩、而且报错完全指不到真正原因」的类型，现在都有守卫：

- **中文文件名会静默 404。** 小程序的 `<image>` 会把中文名做百分号编码，而静态服务
  **故意不做 URL 解码**（为了从结构上杜绝路径穿越）。两边一撞就是 404，而界面因为
  「加载失败回落 emoji」不报任何错 —— 看起来就跟「还没传照片」一模一样。

- **`calc()` 里不能写 `rpx`。** 开发者工具按模拟机宽度在**编译期**把 rpx 换成 px，
  所以模拟器一切正常；真机的屏幕宽度只有运行时才知道，那次替换进不到 calc 内部，
  整条声明被判为非法值丢掉。症状是「一行只显示一个卡片、右边空一大片」。

- **真机调试的通道本身不可靠。** 它把手机所有流量绕经电脑上的开发者工具，
  `wx.login` 和请求都可能长时间不返回。功能测试要用「**预览**」，
  真机调试只在需要看 console / Network 时才用。

- **改了后端忘记重启，会看到「接口不存在」。** 开发者工具里改小程序代码会自动重编译，
  很容易以为「都生效了」，但后端是另一个进程。现在本地用 `npm run dev`
  （`node --watch`），这个坑消掉了。

- **一个流传很广的错误说法**：说不配 downloadFile 合法域名就加载不了图片。
  不对 —— 白名单管的是 `wx.request` / `wx.downloadFile` 这类**API**，`<image>` 是
  **组件**。真机不显示图片时，先去查 HTTPS 和服务器连通性。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `server/` | 后端：数据模型与仓储、HTTP 接口、图片、备份 |
| `miniprogram/` | 微信小程序：主包 + 三个分包 |
| `deploy/` | 阿里云部署：bootstrap、发布脚本、nginx、systemd |
| `tests/` | 607 项测试：合规红线、结构、状态机、**并发与不变量** |
| `scripts/` | 建活动/摊位/物品、设立超管与提权、长图渲染 |
| `prototype/` | 可点击的 HTML 原型（学生端 + 志愿者核销端） |
| `docs/` | 见下表 |

小程序内部大致是这样：

```
miniprogram/
  app.json / app.js / app.wxss   全局配置与样式
  config.js                      换环境只改这一个文件
  data/cats.js                   图鉴的界面文案与分组（猫的资料在服务端）
  services/                      platform（把 wx 收在一处）/ api / session / cats
  pages/                         主包：首页 / 猫猫图鉴 / 我的
  packageBazaar/                 分包：义卖全部页面
  packageCats/                   分包：图鉴详情
  packageAdmin/                  分包：管理端（名单 / 物品 / 活动 / 图鉴 / 角色）
```

**两条微信的硬性规则，已经变成断言：**

- **tabBar 页面必须在主包** —— 所以「猫猫图鉴」的入口页在 `pages/cats`，其余在 `packageCats`
- **主包不能引用分包的文件** —— 所以图鉴的文案常量放主包（分包引用主包是允许的）

`services/platform.js` 把 wx 的能力收在一处，于是**小程序代码能在 Node 里直接测试**，
不需要开发者工具、不需要真机、不需要联网。将来要拆成两个小程序，`packageCats/`
整个搬走即可，义卖一行不用改。
